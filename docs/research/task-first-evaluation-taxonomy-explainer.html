FINAL CRITICAL REVISION · RESEARCH + PRODUCT PROTOTYPE

From a task list to defensible model evidence.

The north star is not a universal skill tree or a prettier leaderboard. It is a traceable chain from a frozen task version to a bounded claim about model behavior, with the protocol, judge, uncertainty, and task distribution still attached.

01 · Corrected thesis

Store evidence in layers. Never collapse the layers into a score.

RSemble should make every conclusion answer five different questions: what was asked, what was produced, how it was measured, what population the claim targets, and how uncertain that claim is.

The compact rule

task demand ≠ observed performance ≠ latent capability. RSemble may connect them, but it must never silently substitute one for another.

02 · Critical audit

Seven conclusions that needed tightening.

The earlier explainer had the right direction but occasionally treated an architectural convenience as a statistical truth, and emerging research as settled doctrine. The finalized version makes those boundaries explicit.

Independence
Too strong

“The task is the atom” implied each task was an independent sample.

Final

A task version is the reproducibility unit. The inference unit may be a task, source case, template family, passage, organization, or another declared cluster. Related tasks can be dependent. [3][14]

Capability
Too essentialist

A stable “model capability profile” sounded like a property the model simply owns.

Final

Generate a versioned report: “under protocol P, on target distribution D, estimator E found this evidence.” It expires when the model, protocol, taxonomy, or target changes.

Taxonomy labels
Unvalidated bridge

Framework labels were presented as if they directly measure machine faculties.

Final

Bloom, DOK, occupational vocabularies, and LLM-generated demand labels are annotation aids or hypotheses. Validate coding guidance, agreement, predictive utility, and failure modes before using labels inferentially. [1][15]

Judge evidence
Underspecified

Judge outputs looked like observations without a strong validity gate.

Final

A repeatable judge can still be systematically wrong. Store judge version, rubric version, order, labels, perturbation tests, agreement beyond chance, and verifier cross-checks. [11][12][13]

Repeated generations
Easy to overcount

20 tasks × 3 runs = 60 rows risked sounding like 60 independent task samples.

Final

Repeated generations estimate within-task stochasticity. They improve measurement for those tasks but do not create new task coverage. Cluster at the task or higher dependence unit.

IRT
Premature precision

An interactive curve made a future latent scale feel implementation-ready.

Final

Keep the intuition, defer production IRT. AI benchmarks often have few, clustered models and many items; recent simulation work finds unreliable inferences under regime mismatch. Use diagnostics and larger, diverse model samples first. [2]

Research maturity
Count over quality

“Thirteen frameworks surveyed” sounded like validation by accumulation.

Final

Source count is not evidence strength. This version distinguishes standards, official systems, peer-reviewed studies, preprints, and repository design documents, then limits what each can justify.

A chain of custody, not a hierarchy of skills.

The data model has two linked planes. The upper plane defines what was intended and frozen. The lower plane records what actually happened and what may be concluded.

W3C PROV maps naturally: immutable records are entities; generation and evaluation are activities; models, judges, people, and software are agents. [5]
Already strong today

Frozen execution

Current RSemble records already preserve experiment snapshots, suite versions, protocol fingerprints, candidate attempts, blinded label maps, judge attempts, and missing-cell repair provenance.

Primary gap

Reusable task identity

Suite packages still embed task objects. Canonical task versions would let the same exact task appear in multiple manifests without copying or losing cross-suite evidence.

Derived, not canonical

Capability claims

Do not store “reasoning = 82” on a model. Store the observations, then materialize a report with its query, inclusion rules, weighting, estimator, and uncertainty.

04 · Bounded foundations

Use each framework for one job. Do not let it colonize the model.

The useful question is not “which framework wins?” It is “what bounded design lesson survives translation into an AI evaluation workbench?”

Established standard or official systemResearch-informed design inputNeeds local validation
Bloom × Webb DOKDescribe intended cognitive work from two anglesEducational frameworks

UseBloom’s revised table separates knowledge type from cognitive process; DOK concerns complexity of engagement rather than simple difficulty. They can prompt richer task annotation. [6][7]

BoundaryThey were built for educational objectives and standards alignment, not as validated latent dimensions of machine intelligence. Labels should remain proposed annotations until a codebook and agreement study support them.

ADeLe general scalesSeparate demand profiles from model ability estimatesPeer-reviewed study

UseThe demand/ability distinction is central. The study reports predictive value across 15 LLMs and 63 tasks using 18 rubrics. [1]

BoundaryThis is strong external evidence for a method, not proof that its 18 scales are RSemble’s correct ontology. Replicate predictive validity on RSemble data before adopting scales or claiming out-of-distribution power.

NIST AI 800-3Declare benchmark accuracy versus generalized accuracyOfficial report

UseExplicitly distinguish performance on a fixed benchmark from performance generalized to a task population. Account for item clusters and report variance structure. [3]

BoundaryA GLMM is not automatically correct. The target population, selection process, link function, random effects, and dependence assumptions must fit the evaluation design.

HELMKeep scenarios, adaptations, and multiple metrics visiblePeer-reviewed benchmark

UseResist one-score evaluation. Preserve scenario context and disaggregated measurements such as accuracy, calibration, robustness, fairness, efficiency, and toxicity where relevant. [8]

BoundaryRSemble is a personal model-pair workbench, not HELM. Borrow the multidimensional reporting principle, not its entire benchmark matrix.

SkillsBenchSeparate domain, operation, modality, interface, and difficultyRepository codebook

UseOrthogonal fields are more defensible than contributor free text; written codebooks, confidence, independent annotation, and agreement checks improve governance. [9]

BoundaryIt is a project taxonomy document, not established psychometrics. Its categories answer SkillsBench’s research question and should not be copied wholesale.

ESCO · O*NET · SFIAGovern stable vocabularies and external mappingsOfficial systems

UseStable identifiers, multilingual labels, relationships, releases, provenance, and deprecation are mature governance lessons. ESCO currently exposes versioned occupation and skill concepts. [10]

BoundaryOccupational competence systems describe human work and labor markets. Use them as optional mappings for task context, never as the core latent structure of model capability.

BIG-bench · GAIA · SNILearn benchmark composition and task diversity patternsBenchmark precedents

UseThey demonstrate community task collections, agentic complexity, structured task schemas, and the practical value of per-task metadata.

BoundaryBenchmark categories are often descriptive and historically contingent. Membership does not establish construct validity or task independence.

W3C PROVRepresent how evidence was producedW3C recommendation

UseEntities, activities, agents, and derivations give RSemble a principled provenance vocabulary for tasks, artifacts, judge events, reports, and reuse. [5]

BoundaryPROV captures lineage; it does not validate a score, judge, taxonomy, or statistical claim.

IRT / RaschModel responses as interactions between models and itemsMature method, risky regime

UseThe central intuition is valuable: raw averages confound item composition, item difficulty, and model performance. A fitted model can estimate latent structure only under explicit assumptions.

BoundaryDo not ship a latent ability number in early phases. Recent AI-specific simulation work shows classical and scalable estimators can fail with small or non-normal model pools. [2]

Agent Skills · DigCompPackaging and human-literacy references onlyPeripheral references

UseAgent Skills suggests portable procedural bundles; DigComp shows a governed multidimensional competence vocabulary.

BoundaryNeither directly validates RSemble’s task taxonomy. Keep them in the research map, not the core implementation dependency.

Bloom’s table remains useful — as a prompt for annotation

Click a cell. The combinations are examples of intended work, not observed model traits.

Proposed annotation

Select a cell

Each educational objective combines a knowledge dimension with a cognitive-process dimension. A real task can occupy multiple cells.

05 · Statistical honesty

Every uncertainty band needs a target.

“Confidence” is incomplete until RSemble states what varies: model generation, judge measurement, the particular task set, or a proposed population of future tasks.

Claim levelWhat variesDefensible outputWhat not to say
Fixed-suite descriptionRepeated generations and judge attempts on these exact 15 tasksPer-task scores, paired differences, judge disagreement, within-task variability

“General business-analytics capability”

Designed task-population inferenceTasks sampled or weighted from an explicitly defined target populationCluster-aware estimate, coverage, weighting sensitivity, uncertainty interval

“Works on future tasks” without a sampling frame

Latent-scale inferenceA fitted measurement model over diverse items and modelsModel diagnostics, fit, identifiability, uncertainty, invariance checks

A stable human-like faculty inferred from a small convenience suite
The PulseFit suite is a designed case battery, not a random sample.

Its 15 tasks provide rich fixed-suite evidence. Generalizing beyond them requires defining the intended universe of D2C subscription analytics work and how this battery represents it.

Teaching model · not a production estimator

IRT intuition, bounded

P(success) = 1 / (1 + e−a(θ−b))

The curve illustrates a model assumption, not an empirical RSemble result. The latent axis gets meaning only from items, population, fit, and validation. [2]

Minimum viable judge validation

Reliability

Can it repeat?

Test–retest consistency, position reversal, formatting and paraphrase perturbations, blind-label stability, and criterion-level disagreement.

Validity

Is it right?

Compare against calibrated human or deterministic anchors, report agreement beyond chance, inspect disagreements, and test domain transfer.

Change control

Did it drift?

Version rubric text, judge model, decoding, candidate order, and validation-set results. A “criterion-preserving” edit can still shift preferences. [13]

07 · Implementation path

Build the evidence spine before the intelligence layer.

The best possible state is reached by making each phase independently useful. No phase needs to pretend later statistical sophistication already exists.

FOUNDATION · EXISTSPreserve current audit recordsExperiment snapshots, protocol fingerprints, candidate and judge attempts, blind maps, repair provenance.
PHASE 1Canonical task versionsImport embedded tasks into stable identities and immutable versions. Manifests reference them.
PHASE 2Observation indexMaterialize artifact × judge/verifier events without deleting raw run records.
PHASE 3Facet governanceVersioned scheme, written codebook, proposed → reviewed → adjudicated workflow, confidence and rationale.
PHASE 4Fixed-suite reportsCoverage, task-level comparisons, paired deltas, judge disagreement, generation variability. No unsupported population claim.
PHASE 5+Validated inferenceDeclare target populations; add weighting, cluster-aware uncertainty, and only later latent models after diagnostics.

Acceptance gates

Data integrity gate

Same task version resolves identically across manifests; hashes and provenance survive export/import; no suite edit mutates completed experiments.

Taxonomy gate

Annotators can apply the codebook independently; disagreement is measured and adjudicated; scheme upgrades do not silently relabel historical reports.

Judge gate

Every active judge protocol has a validation-set result, perturbation tests, rubric fingerprint, and explicit failure policy.

Claim gate

Every aggregate exposes coverage, target, weighting, estimator, uncertainty method, evidence date, and unsupported extrapolations.

Do not implement first

No universal skill tree. No auto-generated “model personality.” No opaque single capability score. No IRT leaderboard from six configured models. No silent in-place addition to a completed experiment. No judge score without judge-quality metadata.

08 · Sources and evidence quality

Sources are inputs, not authority by accumulation.

The final design gives official standards and primary reports more weight for definitions, uses studies for bounded empirical claims, and treats recent preprints as emerging evidence that should influence safeguards rather than settle product truth.
