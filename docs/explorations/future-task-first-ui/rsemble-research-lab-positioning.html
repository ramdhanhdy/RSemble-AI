Positioning thesis

Fusion is a method—not the owner.

The current feature is named and nested as if it exists to prove that Fusion works. In reality it compares competing execution policies and may conclude that Rank, Refine, or a single model is better.

One-time schema replacement

Convert the content. Retire the old contract.

The new Lab becomes the only writable authority. Existing local Fusion content receives one semantic conversion; old stores, routes, payload shapes, and archive imports are removed after the transaction validates.

01
Detect old Fusion schema

Open all seven stores in one read transaction and reject unknown record versions.

02
Build generic Lab records in memory

Preserve semantic IDs, links, artifacts, trial lineage, costs, claim levels, and playbook conclusions.

No writes
03
Validate the complete graph

Every reference resolves; counts and identity crosswalks balance; no record is silently skipped.

Fail closed
04
Write generic stores atomically

Create Study, Trial, Attempt, Observation, Recipe, Model Pool, and Playbook records.

Transactional
05
Delete old active stores and compatibility

Only after the generic graph re-reads successfully. Old routes and Fusion-shaped archive imports stop resolving.

Commit boundary
Failure contract: any unmappable record aborts before the schema commit and leaves the old database untouched. After commit, there is no permanent wrapper, dual authority, legacy route, or old archive reader.
Deliberate compatibility break

No old Fusion contract survives.

This decision simplifies the final architecture but intentionally invalidates old `/evaluations/:suiteId/fusion/:studyId` links and Fusion-shaped archive files after the one-time conversion.
