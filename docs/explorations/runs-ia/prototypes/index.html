Secondary Records
Compare | Evaluations + Records drawer
Compare and Evaluations are primary. Records accessed via a slide-over drawer with search, filters, and attention chips. Run Detail opens as a full page. No proactive badge — secondary access is deliberate, not buried.

Corpus Views
Compare | Runs | Evaluations
Runs stays top-level but gets internal segmented views: Recent, From Compare, From Evaluations, Needs Attention. Views are query filters, not partitions — a run can appear in multiple views. Tests if flatness is the real problem.

Canonical Scenarios to Try
  • Compare a task, then inspect the persisted record (Compare → View record)
  • Open a previous run's configuration in Compare (Run Detail → Open in Compare)
  • From an Evaluation result, reach the exact underlying Judge evidence
  • Find a specific older ad-hoc run with only partial memory of the task
  • Inspect a failed run and understand what went wrong
  • Browse several records because the corpus itself is the object of attention
  • Return to the app and locate recent or unfinished work
