Jobs, not dials.

The 2×2 is a true map of the work. It is a bad steering wheel. Put named jobs in a collapsible sidebar, and treat single-vs-suite as a depth of commitment inside a job — never as a toggle that follows you around.

Companion to two-axis-navigation-spec.md · does not amend it until accepted · no implementation

People do not navigate a classification. They go to a place that does a job. Compare is a place. A “Models × Single” coordinate is a homework problem.

What felt wrong

Two separate instincts, same root cause.

The top is cramped. Compare is already a dense studio — task, candidates, judge, output. A header that also holds four destinations, then two more dials, then utilities, then a live pill, is an instrument cluster sitting on the work. Vertical space is the scarce resource. A sidebar steals unused left margin, not the stage.

The same toggle on every page made the concept feel fake. If Models has Single / Suite, and Strategies has the same Single / Suite, the chrome is saying these are two skins of one empty grid. They are not. Compare is a studio. A benchmark is a matrix. A calibration is a snapshot. A policy study is a protocol. A toggle that teleports you between those is not a mode switch. It is a disguise.

The map is real. The control is the mistake.

RSemble really does have two questions, at two depths:

One task — try itA pinned set — mean it
Which model is better? Comparetoday · daily driver Evaluationstoday · Task Sets + matrix
Which finish policy is worth it? Calibratemissing · snapshot, no claims Policy Studytoday’s Lab

That table belongs in help, empty states, and the first-run story. It does not belong in the chrome as two switches you must compose on every click. Four named destinations and two binary dials carry the same two bits. The dials do not make destinations faster. They make every destination feel like a coordinate.

Rejected — AxisBar

[ Models | Strategies ] [ Single | Suite ]

You compute the place. The same two controls render on every testing surface, so the pages feel like modes of one thing. “Models” collides with the Observatory. Single→Suite is not a zoom level — the entire tool changes.

Recommended — places

Compare · Evaluations · Strategies · Models

You go to a named job. Scale is a sibling or a child inside that job, not a global filter. The Observatory keeps the word Models. Strategies owns studies, calibrate, recipes, and pools — the way Lab already does.

The concept

A collapsible sidebar of jobs. A thin top bar of utilities. Local children only under the job that owns them. No Single / Suite control anywhere in chrome.

How single vs suite actually works

It is not a view filter. It is how serious you are.

  • One task is a try. You want an answer tonight. Compare. Or, for policies, Calibrate.
  • A pinned set is a claim. You want something you can stand on. Evaluations. Or a Policy Study.

Those should be sibling places (or a child under the same job), connected by verbs — not a switch that restyles the current page.

  • From Compare: Run this across a Task Set → Evaluations, draft prefilled.
  • From a suite row: Open this task in Compare.
  • From Calibrate: Test across a Task Set → Policy Study draft. (This verb is the one thing the two-axis spec already got right.)

The relationship is in the work. The nav just names the rooms.

Where Calibrate lives

The missing cell is real. Finish-policy machinery already exists. It should not become a fourth peer of Compare just to complete a diagram.

Nest it under Strategies — Studies · Calibrate · Recipes · Pools — the same local rail Lab already ships. Calibrate is a quick snapshot next to the serious study. It stays honest (one task, no playbook, no claim) because its chrome is quiet, not because a global “Single” dial said so.

If it later earns daily use, promote it. Do not promote it to make the matrix look symmetric.

Why a sidebar, specifically

1
Lab already proved the pattern: a 220px rail for Studies / Recipes / Pools. The shell should use that grammar, not invent a floating capsule and then a second local nav underneath it.
2
Collapsed to ~56px icons, Compare gets its vertical stage back. Expanded, Evaluations and Strategies can show their children without a second top bar. That is the “two types” topology — as grouping, not as a repeated toggle.
3
The old “no left sidebar” decision was for a single split-pane studio. The product is now four workspaces plus a library. That decision is stale. A rail is not the retired 3-panel platform chrome.

What this keeps, and what it drops

Keep from the two-axis spec
  • The 2×2 as a teaching map
  • Calibrate as a real surface (nested)
  • Carry rules: task text, pool, “test across a set”
  • Finish mode stays inside Compare only
  • Observatory is not a testing cell
  • Records / Attention / Search as utilities
  • Renames: Lab → Strategies; Evaluations may become Benchmark later
Drop
  • AxisBar / floating dual dials
  • Single / Suite as global chrome
  • Subject label “Models” (collides with the library)
  • Making Calibrate a top-level peer to complete the grid
  • Replacing four named destinations with two abstract switches

The one decision left

Sidebar grouping is the concept. The only real fork is how loud Calibrate is:

  1. Child of Strategies (recommended). Quiet, honest, matches today’s Lab rail.
  2. Top-level sibling. Only if you expect to live there. Four work items plus Models is a long rail.

Everything else — collapse behavior, header utilities, bridges between places — follows from “jobs, not dials.”
